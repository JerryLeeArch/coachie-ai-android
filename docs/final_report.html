Coachie AI 최종 보고서

AI 기반 목표 설정과 식단 기록을 결합한 Android 모바일 앱

1. 프로젝트 개요 및 기획 의도

앱 이름: Coachie AI

요약: 내가 목표하는 몸을 위해, AI의 도움을 받아 목표를 세우고, 먹는 음식들을 기록하는 앱이다.

기획 의도: 다이어트나 벌크업은 꾸준한 기록과 피드백이 중요하지만, 매 끼니마다 음식명과 영양 정보를 직접 입력하는 일은 번거롭다. Coachie AI는 음식 사진과 간단한 설명을 바탕으로 AI 분석을 제공하고, 목표 섭취량과 실제 섭취량을 비교해 사용자가 자신의 식습관을 쉽게 파악하도록 돕는다.

핵심 가치는 기록 부담 감소, 목표 기반 피드백, 사용자별 데이터 관리이다. 단순 칼로리 기록 앱에서 출발했지만, 개발 과정에서 Firebase Auth, Firestore 동기화, 목표 이력 관리, 신체 측정 기록까지 확장하였다.

2. 시스템 아키텍처 및 기술 스택 선정 이유

3. 핵심 기능 구현 세부 사항

핵심 기능 1: AI 식단 분석 및 리뷰 후 저장

사용자는 음식명, 설명, 사진을 입력하고 AI 분석 결과를 확인한 뒤 저장한다. AI 분석 결과는 그대로 DB에 들어가지 않고, 리뷰 화면을 거쳐 사용자가 확인할 수 있도록 설계했다.

val reviewedMeal = mealReviewRepository.reviewMealDraft(draft)
pendingMealReview = pendingMealReview?.copy(
    isAnalyzing = false,
    reviewedMeal = reviewedMeal,
    errorMessage = null
)

AI 분석 실패 시에도 앱 흐름이 끊기지 않도록 로컬 영양 추정 fallback을 두었다. 이 구조 덕분에 발표 환경에서 네트워크가 불안정해도 식단 기록 기능을 설명할 수 있다.

핵심 기능 2: 목표 계획과 신체 측정값 DB 관리

목표는 단순 설정값이 아니라 기간을 가진 이력 데이터로 저장된다. 사용자가 새 목표를 저장하면 기존 목표 기간을 닫고 새 goal row를 추가하여, 과거 식단 기록을 당시 목표와 비교할 수 있는 기반을 만들었다.

mealDatabase.withTransaction {
    goalDao.closeOverlappingGoalPlans(ownerId, draft.validFromEpochDay)
    goalDao.deleteGoalPlansStartingAtOrAfter(ownerId, draft.validFromEpochDay)
    goalDao.insertGoalPlan(goalPlan)
    goalDao.insertBodyMeasurement(startMeasurement)
}

핵심 기능 3: 사용자별 Firebase 동기화

Firebase Auth의 UID와 로컬 UserAccount를 연결하고, 사용자의 식단/목표/신체 기록을 Firestore의 users/{firebaseUid}/data/current 문서에 스냅샷으로 저장한다. 로그인 시에는 Firestore 스냅샷을 Room DB로 내려받아 다른 실행 환경에서도 같은 데이터를 볼 수 있게 했다.

val snapshot = firestore.collection("users")
    .document(firebaseUid)
    .collection("data")
    .document("current")
    .get()
    .await()

mealDatabase.withTransaction {
    mealDao.deleteMealsForOwner(userAccount.id)
    goalDao.deleteGoalPlansForOwner(userAccount.id)
    goalDao.deleteBodyMeasurementsForOwner(userAccount.id)
    // Firestore snapshot rows are inserted into Room.
}

UI/UX 디자인 콘셉트

Coachie AI는 웰니스/피트니스 앱처럼 차분한 배경색, 초록 key color, 카드형 정보 구조를 사용했다. 홈 화면은 큰 칼로리 게이지와 매크로 요약을 중심으로 구성하고, 목표 설정 화면은 현재 목표 요약을 먼저 보여준 뒤 필요할 때 편집하는 흐름으로 다듬었다.

4. 트러블 슈팅 및 문제 해결

문제 원인 해결
에뮬레이터에서 Firebase 로그인이 실패 에뮬레이터 DNS/네트워크가 불안정하여 Firebase Auth 호스트에 접근하지 못함 -dns-server 8.8.8.8,1.1.1.1 -no-snapshot-load 옵션으로 에뮬레이터를 실행하여 해결
Sandy 계정 로그인 후 데이터가 비어 보임 Firestore에는 데이터가 있었지만 앱이 로그인 시 클라우드 데이터를 Room으로 내려받지 않았음 Firestore snapshot download 기능을 추가하고 로그인/세션 복원 시 Room DB로 import하도록 수정
AI 분석 결과를 그대로 믿기 어려움 음식 사진 기반 영양 분석은 추정값이며 실제 음식량과 다를 수 있음 리뷰 화면과 edit 화면에서 사용자가 영양소 값을 확인/수정할 수 있게 설계
목표 설정값이 앱 재실행 후 유지되지 않거나 과거 목표 추적이 어려움 초기 구현은 목표값을 화면 상태로만 관리 GoalPlanEntity와 BodyMeasurementEntity를 추가하고 목표를 기간 기반 Room 데이터로 저장

5. 프로젝트 후기 및 향후 발전 방향

이번 프로젝트를 통해 Jetpack Compose 화면 설계, Room 기반 데이터 모델링, Firebase Auth/Firestore 연동, AI 분석 흐름을 하나의 앱 안에서 연결하는 경험을 했다. 특히 처음에는 단순 식단 기록 앱으로 시작했지만, 사용자가 실제로 목표를 세우고 데이터를 누적해 볼 수 있으려면 인증, 목표 이력, 신체 기록, 클라우드 동기화가 필요하다는 점을 개발 과정에서 배웠다.

향후에는 Firestore 스냅샷 방식이 아니라 개별 meal/goal 문서 단위의 양방향 동기화, Firebase Storage를 이용한 이미지 업로드, 더 정교한 영양 분석 모델, 알림 클릭 시 바로 식사 기록 화면으로 이동하는 UX, 실제 배포용 release signing을 추가하고 싶다.
