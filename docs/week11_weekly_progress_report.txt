모바일 프로그래밍 개인 프로젝트 11주차 주차별 진행보고서

1. 프로젝트 정보

프로젝트명: AI 기반 식단 기록 관리 앱
제출 주차: 11주차
진행 기간: 2026.05.11 ~ 2026.05.17
개발 환경: Kotlin, Android Studio, Jetpack Compose, Material3, Navigation Compose, Room Database 설계

본 프로젝트는 사용자가 식사 정보를 직접 입력하거나 음식 사진을 기반으로 AI 분석 결과를 참고하여 식단을 기록할 수 있도록 하는 Android 앱이다. 11주차에는 앱의 핵심 화면 구조를 만들고, 화면 전환 흐름과 식단 데이터 모델을 설계하는 데 집중하였다. 실제 사용자가 앱을 실행했을 때 홈 화면에서 오늘의 식단 상태를 확인하고, 음식 추가, 기록 조회, 통계 확인, 목표 설정, 프로필 수정 화면으로 이동할 수 있는 기본 구조를 구현하였다.


2. 11주차 개발 목표

11주차의 목표는 10주차 제안서에서 정한 기능을 실제 Android 프로젝트 구조로 옮기는 것이었다. 한 번에 이미지 선택, 실제 AI API, 데이터베이스 저장까지 모두 완성하기에는 범위가 크기 때문에, 이번 주에는 화면 구성과 데이터 흐름의 뼈대를 먼저 완성하였다.

주요 목표는 다음과 같다.

- Jetpack Compose 기반 주요 화면 구현
- Navigation Compose를 이용한 화면 전환 구조 구현
- LazyColumn을 이용한 식단 기록 리스트 화면 구현
- 홈 화면에서 오늘의 칼로리와 영양소 요약 표시
- 목표 설정 화면과 최근 통계 화면 추가 구현
- Room Database 사용을 위한 Entity, DAO, Database, Repository 설계
- 이미지 선택과 AI 분석 기능을 붙이기 전 사용할 UI 자리와 Mock AI 분석 흐름 구성


3. 현재까지 구현된 전체 기능

현재까지 구현된 기능은 다음과 같다.

- 홈 화면에서 오늘의 섭취 칼로리, 목표 칼로리, 남은 칼로리, 기록 개수 표시
- 탄수화물, 단백질, 지방 섭취량을 막대 그래프와 텍스트로 표시
- 음식 추가 화면에서 음식명, 칼로리, 메모 입력 UI 구현
- 음식 사진 미리보기 영역과 이미지 선택 버튼 자리 구현
- Mock AI 분석 버튼을 눌렀을 때 임시 분석 결과가 표시되는 흐름 구현
- 식단 기록 화면에서 오늘 기록 보기와 전체 기록 보기 필터 구현
- LazyColumn을 이용하여 식단 기록 목록 표시
- 각 식단 기록 카드에 음식명, 기록 시간, 칼로리, 영양소, 메모 표시
- 식단 상세 화면에서 선택한 기록의 상세 정보와 AI 분석 기록 표시
- 최근 통계 화면에서 최근 기록일 평균, 칼로리 경향, 영양 경향 표시
- 목표 설정 화면에서 현재 체중, 목표 체중, 목표 기간, 목표 칼로리, 단백질 목표 입력
- 목표 체중과 기간을 바탕으로 주당 변화량 계산 문구 표시
- 프로필 화면에서 닉네임, 아이디, 비밀번호 수정 UI 구현
- Navigation Compose를 이용하여 홈, 음식 추가, 식단 기록, 식단 상세, 프로필, 목표 설정, 최근 통계 화면 연결
- Room Database를 위한 MealRecord Entity, MealDao, MealDatabase, MealRepository 기본 코드 작성

아직 실제 Room Database와 화면이 완전히 연결된 상태는 아니며, 현재 화면에는 sampleMeals 샘플 데이터를 사용하고 있다. 11주차에는 사용 흐름과 UI 구조를 먼저 검증하고, 12주차에 실제 저장 및 조회 기능을 연결할 계획이다.


4. 화면별 구현 내용

4.1 홈 화면

홈 화면은 앱을 실행했을 때 가장 먼저 보이는 화면으로, 사용자의 오늘 식단 상태를 한눈에 확인할 수 있도록 구현하였다.

구현 기술:
- Jetpack Compose의 Column, Row, Card, Button, OutlinedButton, LinearProgressIndicator 사용
- sampleMeals 데이터 중 오늘 날짜에 해당하는 기록만 필터링
- 오늘 기록의 칼로리, 탄수화물, 단백질, 지방 합계를 계산
- 목표 칼로리와 비교하여 진행률을 LinearProgressIndicator로 표시
- 탄수화물, 단백질, 지방 비율을 하나의 가로 막대 안에 색상별 구간으로 표시
- 프로필 버튼은 닉네임의 첫 글자를 원형 버튼에 표시
- 하단에는 Stats, Add, Goal 버튼을 배치하여 주요 화면으로 이동 가능하게 구성

구현된 내용:
- "오늘의 식단 요약" 카드 구현
- 섭취 칼로리: 1090 kcal / 1900 kcal 형태로 표시
- 기록 개수와 남은 칼로리 표시
- 탄수화물, 단백질, 지방의 현재 섭취량과 목표량 표시
- 기록 보기, 음식 추가, 최근 통계, 목표 설정, 프로필 화면으로 이동하는 진입점 구현

문제 해결 과정:
처음에는 화면마다 데이터를 따로 계산하면 홈 화면, 기록 화면, 통계 화면의 값이 서로 달라질 수 있는 문제가 있었다. 이를 해결하기 위해 sampleMeals 데이터를 공통으로 사용하고, 홈 화면에서는 오늘 날짜 기록만 필터링한 뒤 같은 기준으로 칼로리와 영양소 합계를 계산하도록 구현하였다.

또한 날짜 비교가 기기 날짜와 맞지 않으면 오늘 기록이 비어 보일 수 있었다. 이를 해결하기 위해 isTodayMeal 함수를 만들어 기록의 createdAt 값을 LocalDate로 변환한 뒤 현재 날짜와 비교하도록 하였고, 샘플 데이터 일부는 timestampTodayOf 함수를 통해 실행 날짜 기준의 오늘 기록으로 생성되도록 처리하였다.


4.2 프로필 화면

프로필 화면은 사용자의 닉네임, 아이디, 비밀번호를 수정하는 화면이다.

구현 기술:
- Jetpack Compose의 OutlinedTextField와 Button 사용
- AIDietNavHost에서 rememberSaveable로 닉네임, 아이디, 비밀번호 상태 관리
- PasswordVisualTransformation을 사용하여 비밀번호 입력값을 가림 처리
- ScreenScaffold 공통 레이아웃을 사용하여 상단 뒤로가기 버튼과 제목 표시

구현된 내용:
- 닉네임 입력 필드 구현
- 아이디 입력 필드 구현
- 비밀번호 입력 필드 구현
- 프로필 저장 버튼 구현
- 홈 화면의 원형 프로필 버튼과 연결

문제 해결 과정:
프로필 값은 여러 화면에서 참조될 수 있기 때문에 ProfileScreen 내부에만 상태를 두면 홈 화면의 프로필 이니셜과 동기화되지 않는 문제가 생길 수 있었다. 이를 해결하기 위해 AIDietNavHost에서 rememberSaveable로 상태를 관리하고, ProfileScreen에는 값과 변경 콜백을 전달하는 방식으로 구현하였다.


4.3 음식 추가 화면

음식 추가 화면은 사용자가 직접 음식명을 입력하고 칼로리와 메모를 작성하는 화면이다. 이후 이미지 선택 기능과 실제 AI 분석 기능이 연결될 예정이므로, 11주차에는 미리보기 영역과 Mock AI 분석 흐름을 먼저 구현하였다.

구현 기술:
- OutlinedTextField를 이용한 음식명, 칼로리, 메모 입력
- KeyboardOptions를 사용하여 칼로리 입력 키보드를 숫자 입력에 맞게 설정
- calories 값은 숫자만 남도록 필터링
- Card와 Box를 사용하여 음식 사진 미리보기 영역 구성
- remember와 mutableStateOf를 이용하여 입력값과 AI 분석 결과 상태 관리
- Mock AI 분석 버튼 클릭 시 임시 분석 결과 문자열 갱신

구현된 내용:
- 음식명 기본값 "닭가슴살 샐러드" 표시
- 칼로리 기본값 420 kcal 표시
- 메모 입력 영역 구현
- 음식 사진 미리보기 영역 구현
- 이미지 선택 기능 연결 예정 버튼 구현
- AI 분석 결과 카드 구현
- Mock AI 분석 버튼 구현
- 먹은 음식 추가 버튼 클릭 시 식단 기록 화면으로 이동

문제 해결 과정:
11주차 단계에서 실제 이미지 선택과 외부 AI API를 먼저 붙이면 API 키 관리, 네트워크 요청, 이미지 URI 처리까지 동시에 해결해야 해서 기능 범위가 커지는 문제가 있었다. 이를 해결하기 위해 이번 주에는 실제 API 대신 Mock AI 분석 버튼을 두어 사용자가 "사진 선택 -> 분석 결과 확인 -> 저장"으로 이어질 흐름을 미리 확인할 수 있게 했다.

또한 칼로리 입력란에 문자가 들어가면 이후 계산 과정에서 오류가 발생할 수 있기 때문에, onValueChange에서 숫자만 허용하도록 필터링하였다.


4.4 식단 기록 화면

식단 기록 화면은 저장된 식단 기록을 리스트 형태로 보여주는 화면이다. 과제 요구사항 중 "1개 이상의 리스트 페이지"를 충족하는 핵심 화면이다.

구현 기술:
- LazyColumn을 사용하여 식단 기록 목록 표시
- Today, All 필터 상태를 enum class로 관리
- 선택된 필터는 Button, 선택되지 않은 필터는 OutlinedButton으로 표시
- sampleMeals 데이터를 오늘 기록 또는 전체 기록으로 필터링
- 각 기록은 Card와 Row, Column을 조합하여 카드형 리스트 항목으로 표시
- 기록 카드를 클릭하면 Navigation Compose를 통해 식단 상세 화면으로 이동

구현된 내용:
- "오늘 기록 보기" 필터 구현
- "전체 기록 보기" 필터 구현
- 오늘 기록에는 2026.05.15 기준 샘플 기록 3개 표시
- 전체 기록에는 오늘 기록과 이전 기록을 함께 표시
- 각 항목에 사진 자리, 음식명, 날짜/시간, 칼로리, 탄수화물/단백질/지방, 메모 표시
- 빈 기록 상태 메시지 UI 구현

문제 해결 과정:
처음에는 모든 식단 기록을 한 화면에만 보여주면 오늘 섭취량 확인과 전체 기록 확인의 목적이 섞이는 문제가 있었다. 이를 해결하기 위해 "오늘 기록 보기"와 "전체 기록 보기" 필터를 분리하였다. selectedFilter 상태를 remember로 관리하여 버튼을 누를 때마다 표시되는 리스트가 바뀌도록 구현하였다.

또한 기록 수가 늘어났을 때 Column으로 구현하면 스크롤 성능과 관리가 어려워질 수 있기 때문에 LazyColumn을 사용하였다. 이를 통해 많은 기록이 생겨도 필요한 항목만 효율적으로 그릴 수 있는 구조를 만들었다.


4.5 식단 상세 화면

식단 상세 화면은 식단 기록 화면에서 특정 항목을 선택했을 때 해당 음식의 자세한 정보를 보여주는 화면이다.

구현 기술:
- Navigation Compose의 navArgument를 사용하여 mealId를 Long 타입으로 전달
- Route.MealDetail.createPath(mealId) 함수로 상세 화면 경로 생성
- sampleMeals에서 전달받은 id와 일치하는 기록 검색
- Card를 사용하여 기본 정보, 영양 정보, AI 분석 기록을 영역별로 분리

구현된 내용:
- 저장된 음식 이미지 표시 영역 구현
- 음식명, 기록 시간, 칼로리, 메모 표시
- 탄수화물, 단백질, 지방 정보 표시
- AI가 추정한 음식명과 칼로리 표시
- 뒤로가기 버튼으로 식단 기록 화면 복귀

문제 해결 과정:
리스트 항목을 클릭했을 때 어떤 기록을 상세 화면에 보여줄지 구분해야 했다. 단순히 상세 화면 하나만 열면 항상 같은 데이터가 보이는 문제가 생긴다. 이를 해결하기 위해 Navigation 경로에 mealId를 포함하고, 상세 화면에서 해당 id를 기준으로 데이터를 찾도록 구현하였다.


4.6 최근 통계 & 경향 화면

최근 통계 화면은 사용자가 최근 식단 기록의 평균과 변화 추세를 확인하는 화면이다.

구현 기술:
- sampleMeals를 날짜별로 groupBy하여 DailyNutritionStats 데이터로 변환
- 날짜별 칼로리, 기록 개수, 탄수화물, 단백질, 지방 합계 계산
- 최근 기록일 평균 칼로리, 평균 단백질, 평균 기록 개수 계산
- 직전 기록일과 최신 기록일의 칼로리 차이를 비교하여 문장으로 표시
- LinearProgressIndicator를 이용하여 칼로리 경향과 영양 경향 표시
- 날짜 표시는 MealDateFormatter 유틸 함수 사용

구현된 내용:
- 최근 기록일 평균 카드 구현
- 평균 칼로리, 평균 단백질, 평균 기록 개수 표시
- 직전 기록일 대비 칼로리 변화 문구 표시
- 날짜별 칼로리 경향 표시
- 날짜별 영양 경향 표시

문제 해결 과정:
통계 화면은 단순히 샘플 값을 직접 적어두면 이후 DB 데이터로 바꾸기 어렵다. 그래서 sampleMeals를 날짜별로 묶고 합산하는 함수를 별도로 작성하였다. 이 방식은 12주차에 Room DB에서 가져온 리스트로 데이터 출처만 바꾸면 같은 계산 로직을 계속 사용할 수 있다는 장점이 있다.


4.7 목표 설정 화면

목표 설정 화면은 사용자가 현재 체중, 목표 체중, 목표 기간, 하루 목표 칼로리, 단백질 목표를 입력하는 화면이다.

구현 기술:
- OutlinedTextField와 KeyboardOptions를 사용하여 숫자 입력 UI 구현
- 체중 입력은 소수점 하나만 허용하도록 filterDecimalInput 함수 사용
- 목표 기간, 목표 칼로리, 단백질 목표는 숫자만 입력되도록 필터링
- buildGoalSummary 함수에서 현재 체중, 목표 체중, 목표 기간을 계산하여 변화량 문구 생성
- 목표 칼로리와 단백질 목표는 AIDietNavHost의 rememberSaveable 상태로 관리하여 홈 화면과 최근 통계 화면에 반영

구현된 내용:
- 현재 체중 입력
- 목표 체중 입력
- 목표 기간 입력
- 주당 체중 변화량 계산 문구 표시
- 하루 목표 칼로리 입력
- 단백질 목표 입력
- 목표 저장 버튼 구현

문제 해결 과정:
체중 입력에는 소수점이 필요하지만, 문자가 들어가거나 소수점이 여러 개 들어가면 계산이 불가능해지는 문제가 있었다. 이를 해결하기 위해 filterDecimalInput 함수를 만들고 숫자와 첫 번째 소수점만 허용하도록 처리하였다.

또한 목표 칼로리와 단백질 목표는 홈 화면과 통계 화면에서도 사용되므로 화면 내부 상태로만 두지 않고 AIDietNavHost에서 관리하였다. 이를 통해 목표 설정 화면에서 값을 수정하면 다른 화면 계산에도 같은 값이 사용될 수 있는 구조를 만들었다.


5. 데이터 구조 및 저장 설계

11주차에는 실제 DB 연결 전 단계로 Room Database 설계 코드를 작성하였다.

MealRecord Entity의 주요 필드는 다음과 같다.

- id: 기록 고유 번호
- foodName: 음식명
- calories: 칼로리
- carbsGram: 탄수화물 g
- proteinGram: 단백질 g
- fatGram: 지방 g
- memo: 사용자 메모
- imageUri: 음식 사진 URI
- aiFoodName: AI가 추정한 음식명
- aiCalories: AI가 추정한 칼로리
- createdAt: 기록 생성 시간

MealDao에는 다음 기능을 설계하였다.

- 전체 식단 기록을 최신순으로 관찰하는 observeMealRecords
- id 기준으로 단일 기록을 조회하는 getMealRecord
- 기록 추가 insertMealRecord
- 기록 수정 updateMealRecord
- 기록 삭제 deleteMealRecord

MealRepository는 화면 또는 ViewModel에서 DAO를 직접 다루지 않도록 중간 계층으로 작성하였다. 12주차에는 ViewModel을 추가하여 Repository와 Compose 화면을 연결할 예정이다.


6. 공통 UI 및 화면 전환 구현

여러 화면에서 공통으로 필요한 상단 앱바와 배경을 ScreenScaffold로 분리하였다. ScreenScaffold는 Material3 Scaffold와 TopAppBar를 감싸고 있으며, 화면 제목과 뒤로가기 버튼을 선택적으로 받을 수 있도록 만들었다.

화면 전환은 Navigation Compose로 구현하였다. 현재 Route는 다음과 같이 구성되어 있다.

- home
- addMeal
- mealList
- mealDetail/{mealId}
- profile
- goalSettings
- recentStats

이를 통해 과제 조건인 4개 이상의 화면 전환을 충족하며, 실제로 홈 화면을 중심으로 여러 기능 화면으로 이동할 수 있다.


7. 11주차 문제 해결 과정 요약

이번 주 개발에서 가장 중요했던 문제는 기능 범위 조절이었다. 제안서에는 식단 기록, 이미지 선택, AI 분석, 데이터베이스 저장이 모두 포함되어 있었지만, 이를 한 번에 구현하면 오류가 생겼을 때 원인을 찾기 어렵고 제출 일정에도 부담이 커질 수 있었다.

이를 해결하기 위해 기능을 다음 순서로 나누었다.

1. 먼저 화면 구조와 Navigation을 구현하였다.
2. 실제 DB 저장 전 sampleMeals를 사용하여 UI와 계산 로직을 검증하였다.
3. Room Database는 Entity, DAO, Database, Repository까지 설계해 두었다.
4. 이미지 선택은 실제 파일 선택 전 미리보기 영역과 버튼 위치를 먼저 만들었다.
5. AI 분석은 실제 외부 API 대신 Mock AI 분석 버튼으로 흐름을 먼저 구현하였다.
6. 날짜 표시와 오늘 기록 필터링은 MealDateFormatter와 isTodayMeal 함수로 분리하였다.
7. 여러 화면에서 쓰는 목표값과 프로필 값은 AIDietNavHost에서 rememberSaveable로 관리하였다.

이 과정을 통해 앱의 핵심 사용 흐름을 먼저 완성하고, 다음 주에 실제 저장 기능과 이미지 기능을 붙일 수 있는 기반을 만들었다.


8. 현재 한계점

11주차 기준으로 아직 완성되지 않은 부분은 다음과 같다.

- 음식 추가 화면의 입력값이 실제 Room Database에 저장되지는 않음
- 식단 기록 화면은 현재 sampleMeals 샘플 데이터를 표시함
- 이미지 선택 버튼은 UI만 있고 실제 갤러리 선택 기능은 아직 연결되지 않음
- 음식 사진 미리보기 영역은 실제 이미지 대신 placeholder로 표시됨
- Mock AI 분석은 실제 AI API가 아니라 임시 결과 문자열을 표시함
- 목표 설정과 프로필 값은 앱 실행 중 상태로만 관리되며, 영구 저장은 아직 구현하지 않음
- 영양소 입력은 음식 추가 화면에 아직 직접 입력 UI가 없고, 샘플 데이터 중심으로 표시됨

이 한계점들은 12주차와 13주차 구현 범위에서 단계적으로 해결할 예정이다.


9. 12주차 구현 예정 내용

12주차에는 11주차에 만든 화면과 데이터 설계를 실제 동작하는 저장 기능으로 연결할 예정이다.

구현 예정 기능은 다음과 같다.

- Room.databaseBuilder를 사용하여 앱에서 MealDatabase 인스턴스 생성
- MealRepository와 ViewModel 구조 추가
- AddMealScreen에서 입력한 음식명, 칼로리, 메모를 MealRecord로 변환하여 DB 저장
- MealListScreen에서 sampleMeals 대신 Room DB의 Flow 데이터를 관찰하여 리스트 표시
- MealDetailScreen에서 mealId 기준으로 DB의 실제 기록 상세 조회
- 음식 추가 후 저장되면 식단 기록 화면에 새 기록이 반영되도록 구현
- 오늘 기록 보기와 전체 기록 보기 필터를 DB 데이터 기준으로 동작하도록 수정
- 이미지 선택 기능 구현
- 선택한 이미지 URI를 AddMealScreen 미리보기 영역에 표시
- 선택한 이미지 URI를 MealRecord.imageUri에 저장하는 구조 구현
- Mock AI 분석 결과를 단순 텍스트 표시에서 음식명, 칼로리 입력값에 반영하는 방식으로 개선
- 입력값 검증 추가: 음식명 비어 있음, 칼로리 미입력, 잘못된 숫자 입력 처리
- 빈 리스트 상태와 저장 성공 후 화면 이동 흐름 개선

12주차의 핵심 목표는 "현재 보이는 화면이 실제 사용자 입력 데이터와 연결되도록 만드는 것"이다. 즉, 11주차가 화면과 구조 중심이었다면, 12주차는 저장, 조회, 상세 표시, 이미지 선택까지 실제 앱 기능으로 완성하는 단계가 될 것이다.
